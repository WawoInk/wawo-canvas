# API 响应

业务接口统一返回：

```json
{
  "code": 0,
  "data": {},
  "msg": "ok"
}
```

- `code: 0` 表示成功，结果放在 `data`。
- `code: 1` 表示业务失败。除冲突和真实路由错误外，业务失败通常仍使用 HTTP 200。
- `msg` 是可以展示给用户的安全消息；未声明为安全的内部错误统一显示“操作失败”。
- 乐观锁冲突使用 HTTP 409 和 `code: -1`。

## AI Compatibility 流式响应

AI Compatibility Proxy 的成功响应保留上游响应格式。响应 `Content-Type` 为 `text/event-stream`、`application/x-ndjson` 或 `application/ndjson` 时，服务端逐块转发并及时 Flush，不发送 `Content-Length`；客户端取消或断开连接时，同一个请求的取消信号会传播到上游。

上游在流开始前返回 4xx/5xx 时，继续返回可展示的 `{ code: 1, data: null, msg }` 业务失败响应，不以成功 SSE/NDJSON 的形式转发。流已经开始后发生客户端取消、上游读取错误或下游写入错误时，服务端直接结束流，不再向已经开始的流追加 JSON 错误，也不得把任务记录为完整成功。

任务审计不保存 Authorization、真实 API Key 或 URL 查询参数值。Chat Compatibility 的持久化 `request_body`、`response_body` 和 `raw_error` 只记录固定 omission marker，任务错误只保存稳定的规范 code 与通用消息；该最小化仅作用于审计和持久化任务错误，不修改实际转发给客户端的上游内容，也不改变客户端即时错误合同。普通 JSON、图片、音频和视频 Compatibility 响应继续沿用原有非流式行为。Chat Compatibility 若上游返回 OpenAI `usage` 或 Gemini `usageMetadata`，服务端会将归一化后的 `inputTokens`、`outputTokens`、`totalTokens` 写入现有 `generation_tasks.metadata.usage`，不把聊天正文写入审计。Brainstorm Agent 每轮先读取管理员公开文本配置，强制使用 `defaultTextModel` 对应的 remote channel，并以 `X-Source: brainstorm_agent` 标记任务；不使用浏览器本地模型或 API Key。

## Brainstorm Workspace API

Brainstorm Workspace 的 JSON API 使用当前登录账号。为兼容旧 project 模式，路由继续保留 `{projectId}`；独立入口使用保留的 `__brainstorm__` scope 作为隔离键，不创建、读取或要求真实 Storyboard Project：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/v1/storyboards/{projectId}/conversations` | 分页读取 Conversation |
| `POST` | `/api/v1/storyboards/{projectId}/conversations` | 创建 Conversation |
| `PUT` | `/api/v1/storyboards/{projectId}/conversations/{conversationId}/title` | 重命名 Conversation |
| `DELETE` | `/api/v1/storyboards/{projectId}/conversations/{conversationId}` | 删除 Conversation 及其 Messages |
| `GET` | `/api/v1/storyboards/{projectId}/conversations/{conversationId}/messages` | 分页读取平铺 Message 图和当前 Conversation |
| `POST` | `/api/v1/storyboards/{projectId}/conversations/{conversationId}/turns` | 以 `append` 或 `regenerate` 创建原子 Turn |
| `PUT` | `/api/v1/storyboards/{projectId}/conversations/{conversationId}/messages/{messageId}/assistant` | 按 `expectedRevision` CAS 更新 Assistant 状态和完整 output |
| `POST` | `/api/v1/storyboards/{projectId}/conversations/{conversationId}/messages/{messageId}/continue` | 按 `expectedRevision` 继续 terminal Assistant |
| `GET` | `/api/v1/storyboards/{projectId}/memories` | 分页读取已确认 Brainstorm Memory |
| `POST` | `/api/v1/storyboards/{projectId}/memories` | 创建已确认 Brainstorm Memory；standalone 只允许工作区 scope |
| `PUT` | `/api/v1/storyboards/{projectId}/memories/{memoryId}` | 更新已确认 Brainstorm Memory |
| `DELETE` | `/api/v1/storyboards/{projectId}/memories/{memoryId}` | 删除已确认 Brainstorm Memory |

Conversation 和 Memory 列表使用 `page/pageSize`，返回 `{items,total}`；Message 列表额外返回 `conversation`，并按 `created_at ASC, id ASC` 返回平铺消息。`append` 在一个数据库事务中创建 User Message、pending Assistant Placeholder 并更新 `currentMessageId`；`regenerate` 在原 User Message 下创建新的 Assistant sibling，`continue` 复用原 terminal Assistant，不创建 sibling。

Assistant 更新和 continue 必须提交 `expectedRevision`。同一 Conversation 已有 active Turn、幂等键或 ID 被不同语义复用、revision 过期或生命周期转换无效时返回 HTTP 409、`code: -1`，并在可用时通过 `data.current` 返回当前对象。Storyboard Project、Brainstorm Workspace、Conversation、Message 或 Memory 不存在及 scope 越权统一返回 HTTP 404 和安全消息，不区分资源不存在与无权访问。

这些 JSON API 只持久化 Brainstorm 领域状态，不承载模型流。Stop 没有独立路由：浏览器先取消当前 Provider 请求，再通过 Assistant CAS 保存 `cancelled` 或相应终态；用户 Retry 等价于新的 `regenerate`。模型 Completion 只会在首个输出前对网络错误、超时、429、500、502、503 或 504 最多自动重试一次；Abort、400、参数错误、已经产生文本/Tool delta 或已经执行写操作后不自动重试。Summary 由浏览器 Runtime 在同一 Conversation 页面内按分支派生，使用 20k token trigger 和 8k token retain；分支 boundary 缺失时重建，刷新后从持久 Message 历史重新生成。Summary 是非可信上下文，没有独立数据库字段、数据表或 API。固定系统规则与当前用户输入无法装入 Context 时，浏览器会在调用 Completion 前返回可读的 `CONTEXT_BUDGET_EXCEEDED`，不会创建模型请求。

## 结构化生成错误

第一方生成接口的可定位错误在同一信封的 `data` 中返回：

```json
{
  "code": 1,
  "data": {
    "code": "INVALID_SETTING",
    "retryable": false,
    "fieldPath": "intent.settings.durationSeconds",
    "resourceId": "canvas-node-id"
  },
  "msg": "设置值超出允许范围"
}
```

字段说明：

- `code`：稳定的平台错误码，不暴露供应商私有错误码。
- `retryable`：客户端是否适合在不修改输入的情况下重试。
- `fieldPath`：命令中的错误字段路径；没有具体字段时可省略。
- `resourceId`：关联的 Canvas 节点或平台资源 ID；不适用时省略。

视频 Generation Run 会把可判断的上游失败归一为稳定错误码，原始供应商错误只保留在脱敏审计中：

| 错误码 | 含义 |
| --- | --- |
| `UPSTREAM_TIMEOUT` | 上游请求或视频生成超时 |
| `UPSTREAM_RATE_LIMITED` | 上游限流或额度繁忙 |
| `UPSTREAM_UNAVAILABLE` | 上游服务或网络暂时不可用 |
| `UPSTREAM_AUTH_FAILED` | 上游认证失败 |
| `UPSTREAM_PERMISSION_DENIED` | 上游拒绝当前凭据访问 |
| `UPSTREAM_NOT_FOUND` | 上游任务或生成接口不存在 |
| `CONTENT_REJECTED` | 内容未通过上游安全审核 |
| `INVALID_REQUEST` | 生成参数、输入或接口要求不匹配 |

Canvas 还会按已有平台错误码区分 `GENERATION_TIMEOUT`、`TASK_SYNC_TIMEOUT`、`MODEL_CONFIGURATION_INVALID`、`RESULT_PERSIST_FAILED` 和 `RESULT_FILE_MISSING`。客户端收到稳定 `code` 时优先按错误码显示具体原因；旧响应缺少 `retryable` 时按 `false` 处理。

取消、回调等操作错误至少返回稳定的 `data.code`。异步失败通过 `GET /api/v1/generations/{id}` 的任务 `error` 字段返回同一套归一化信息。

第一方生成创建响应丢失时，已认证客户端可调用 `GET /api/v1/generations/client-requests/{clientRequestId}`，按当前用户和幂等请求 ID 找回同一任务。不存在或不属于当前用户时成功响应的 `data` 为 `null`；该查询不会创建新任务或改变任务状态。

Canvas 与远程视频创作台都使用第一方视频 Generation Run：客户端提交 `source: "canvas"` 或 `source: "video_workbench"`，服务端统一负责路由、计费、审计、轮询、结果物化和终态仲裁。远程图片仍使用异步 compatibility 路由；任务在平台文件 `fileId` 写入 metadata 后才进入成功状态。

积分、价格、折扣倍率和上游 credits 等十进制字段在 JSON 中统一使用字符串，避免 JavaScript `number` 丢失精度；客户端提交这类字段时也应发送十进制字符串，例如 `"2.5"`。

## 企业基础接口

平台管理员使用现有 Bearer JWT 调用以下接口，响应继续使用统一信封：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/admin/enterprises` | 按 `keyword/page/pageSize` 查询企业、主账号、成员数和主账号余额 |
| `POST` | `/api/admin/enterprises` | 在同一事务中创建企业及唯一主账号 |
| `POST` | `/api/admin/enterprises/{id}/status` | 设置企业 `active/disabled` 状态 |
| `POST` | `/api/admin/enterprises/{id}/owner/status` | 设置主账号 `active/ban` 状态 |
| `POST` | `/api/admin/enterprises/{id}/owner/password` | 重置主账号密码并使旧会话失效 |
| `POST` | `/api/admin/enterprises/{id}/credits` | 使用 `{ delta, reason }` 按增量调整主账号积分；`delta` 不能为 0，扣减后余额不能为负 |

企业积分调整不接受客户端提交最终余额。服务端锁定主账号余额后应用 `delta`，并在同一数据库事务中写入 `admin_adjust` 流水；流水的 `userId` 是目标主账号，`relatedId` 是平台管理员，`remark` 保存调整原因。`GET /api/admin/credit-logs` 支持 `keyword/type/start_time/end_time/page/pageSize`，日期按闭区间筛选 `createdAt`，每条记录附带当前对应用户的 `username`；使用 `type=admin_adjust` 可筛选平台调整记录。企业账号不能再通过 `/api/admin/users/{id}/credits` 覆盖余额。

管理后台使用日志 `GET /api/admin/generation-tasks` 同样支持 `start_time/end_time` 日期闭区间筛选。前端日期范围会按本地首日开始时间和末日结束时间转换为 ISO 时间戳。

管理员可对失败或已取消且缺少退款流水的任务调用 `POST /api/admin/generation-tasks/{id}/refund`，请求体为 `{ "reason": "..." }`。服务端从该任务的 `ai_consume` 流水取得实际退款金额并以 `ai_refund` 写回原扣费账号；任务 ID 已退款时重复调用不重复入账，运行中任务、无消费流水任务和空原因请求会被拒绝。详情接口 `GET /api/admin/generation-tasks/{id}` 返回 `canRepairRefund`，用于控制后台操作入口。

`/api/auth/login` 和 `/api/auth/me` 的公开用户信息可包含 `enterpriseId`、`enterpriseName`、`enterpriseRole` 和 `enterpriseStatus`。企业范围由服务端当前用户推导，不接受客户端提交企业 ID 来切换身份。

当前登录用户使用以下接口维护自己的账户，用户名、平台角色、积分和企业身份不能通过这些接口修改：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `PUT` | `/api/v1/account/profile` | 修改自己的昵称和邮箱 |
| `POST` | `/api/v1/account/password` | 校验当前密码后修改新密码，并使旧 JWT 失效 |
| `GET` | `/api/v1/credit-logs` | 按 `keyword/type/start_time/end_time/page/pageSize` 查询当前账号积分流水 |
| `GET` | `/api/v1/enterprise/summary` | 有效企业账号读取企业名称、角色、状态和成员数；个人账号拒绝访问 |
| `PUT` | `/api/v1/account/enterprise` | 企业主账号修改本企业名称 |

企业主账号使用以下接口管理本企业 `member`。企业范围只从当前 JWT 对应账号推导；跨企业或非成员目标统一返回“成员不存在或无权操作”。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/v1/enterprise/members` | 按 `keyword/page/pageSize` 分页搜索本企业成员 |
| `GET` | `/api/v1/enterprise/credit-logs` | 主账号按 `memberId/type/keyword/start_time/end_time/page/pageSize` 查询本企业主账号和当前成员的积分流水 |
| `POST` | `/api/v1/enterprise/members` | 创建固定为 `user/member`、初始积分为零的子账号 |
| `POST` | `/api/v1/enterprise/members/{id}/status` | 设置成员 `active/ban` 状态 |
| `POST` | `/api/v1/enterprise/members/{id}/password` | 重置成员密码并使旧 JWT 失效 |
| `POST` | `/api/v1/enterprise/members/{id}/credits` | 使用 `{ action, amount, requestId }` 分配或收回成员积分；`action` 为 `allocate/reclaim`，`amount` 必须为正数 |

积分操作响应同时返回主账号最新积分 `ownerCredits` 和更新后的 `member`。客户端请求 ID 最长 128 字符；相同账号、操作类型和请求 ID 的重试只生效一次，复用请求 ID 但修改成员或数量会被拒绝。

`start_time/end_time` 按闭区间筛选 `createdAt`。企业积分流水只接受当前企业主账号查询，企业 ID 始终从认证账号推导；客户端提交 `enterpriseId`、其他企业的 `memberId` 或无关流水 ID 不会扩大范围。列表包含 `admin_adjust`、`enterprise_allocate`、`enterprise_reclaim`、`ai_consume` 和 `ai_refund`，每条记录附带所属账号的 `username/displayName`；子账号继续使用 `/api/v1/credit-logs` 查看自己的个人流水。

## 火山引擎资产接口

管理员通过独立的 `VolcAssetConfig` 设置项配置一个或多个上游素材库。配置 JSON 对齐 xvanai-new，支持 `volcengine`、`volcengine-custom`、`newapi` 和 `custom_formats`；管理端读取时仅清空 `secret_key` 与 `access_token`，提交空值会保留服务端已保存的秘密。上游地址、Access Key、签名密钥和访问令牌不会进入普通用户响应。

用户侧资产 Action 使用当前登录账号和企业身份服务端推导作用域，不接受客户端提交的 `enterpriseId`、`userId`、`GroupId` 或 `ProjectName` 作为授权依据。每个个人或企业用户与 outbound 组合自动绑定独立上游素材分组；分组管理 Action 仅平台管理员可调用。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/v1/volcengine-assets/outbounds` | 返回当前可用 outbound 的安全元数据 |
| `GET` | `/api/user/assets/outbounds` | 与 xvanai-new 兼容的安全 outbound 元数据别名 |
| `POST` | `/api/v1/doubao/open/ListAssets` | 列出当前账号作用域内的远端素材 |
| `POST` | `/api/v1/doubao/open/GetAsset` | 查询并校验当前账号可访问的远端素材 |
| `POST` | `/api/v1/doubao/open/CreateAsset` | 登记 `http/https` 远端媒体 URL |
| `POST` | `/api/v1/doubao/open/UpdateAsset` | 重命名当前账号的远端素材 |
| `POST` | `/api/v1/doubao/open/DeleteAsset` | 删除当前账号的远端素材引用 |
| `POST` | `/api/v1/doubao/open/{CreateAssetGroup...DeleteAssetGroup}` | 管理员素材分组操作；同样支持 `/v1/...` 兼容路径 |
| `GET/POST` | `/api/admin/volcengine-assets/config` | 管理员读取脱敏配置或保存 `{ "config": "..." }` |

请求可通过 `X-Asset-Outbound`（或配置的选择请求头）或 `?outbound=<id>` 选择 outbound；未指定时依次使用默认 outbound 和首个可用 outbound。配置 `failover` 时，连接失败、超时、429 或 5xx 会按候选顺序改用下一个已配置 outbound；参数、鉴权、越权和素材不存在等业务错误不会切换。

火山引擎资产上游请求由后端发起，并遵循部署环境提供的标准 HTTP(S) 代理设置（如 `HTTP_PROXY`、`HTTPS_PROXY` 和 `NO_PROXY`）；未配置代理时直接连接上游。用户浏览器只调用平台 API，远端图片、视频和音频 URL 仅用于页面预览。素材库引用删除不会删除 URL 指向的原始媒体。

## 企业素材接口

有效企业的 `owner/member` 使用独立接口读取本企业素材，企业范围只从当前认证账号推导。`owner` 可管理素材和企业媒体文件，`member` 只读、预览和下载。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/v1/enterprise/assets` | 按 `keyword/type/tag/page/pageSize` 查询本企业文本、图片、视频素材和可用标签 |
| `GET` | `/api/v1/enterprise/assets/{id}` | 读取本企业素材详情；媒体素材返回短期 `url` |
| `POST` | `/api/v1/enterprise/assets` | 主账号新增文本或已上传媒体素材；媒体使用 `fileId` 关联企业文件 |
| `PUT` | `/api/v1/enterprise/assets/{id}` | 主账号更新本企业素材元数据或媒体关联 |
| `DELETE` | `/api/v1/enterprise/assets/{id}` | 主账号删除本企业素材及其关联企业文件记录 |
| `POST` | `/api/v1/enterprise/assets/{id}/copy` | 当前企业主账号或成员将本企业素材复制为自己的个人素材；媒体服务端复制为新的个人文件 |
| `POST` | `/api/v1/enterprise/files` | 主账号上传图片/视频企业文件，表单字段为 `fileType` 和 `file` |
| `GET` | `/api/v1/enterprise/files/{id}` | 企业有效账号读取文件元数据和短期预签名 `url` |
| `GET` | `/api/v1/enterprise/files/{id}/content` | 企业有效账号下载文件内容 |
| `PUT` | `/api/v1/enterprise/files/{id}` | 主账号替换企业文件内容和元数据 |
| `DELETE` | `/api/v1/enterprise/files/{id}` | 主账号删除企业文件 |

素材和文件响应只返回短期预签名 `url`，不返回原始对象存储 Key。个人 `/api/v1/files` 的列表、详情和上传确认响应也使用 `url` 字段；现有 Canvas 仍通过 `fileId` 重新读取该 URL。文件读取、下载、签名、更新和删除分别执行企业范围与角色校验；企业或成员停用后不再签发新的媒体 URL。请求体中的素材 ID、文件 ID、企业 ID 和创建者 ID均不会改变服务端授权范围。企业素材响应包含 `enterpriseId`、创建者 `userId/creatorName`，但不会写入个人素材同步缓存。

复制接口成功后返回新的个人素材记录。文本只创建个人素材记录；图片和视频通过对象存储服务端复制创建新的个人文件和个人素材，返回的 `fileId` 与企业源文件不同。复制前仍按当前账号推导企业范围，源企业素材删除或源文件失效不会影响已完成的个人副本；对象复制失败或数据库事务回滚时不保留可见个人记录。
