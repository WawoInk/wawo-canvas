# API 响应

业务接口统一返回：

```json
{
  "code": 0,
  "data": {},
  "msg": "ok"
}
```

- `code: 0` 表示成功，结果放在 `data`。
- `code: 1` 表示业务失败。除冲突和真实路由错误外，业务失败通常仍使用 HTTP 200。
- `msg` 是可以展示给用户的安全消息；未声明为安全的内部错误统一显示“操作失败”。
- 乐观锁冲突使用 HTTP 409 和 `code: -1`。

## 结构化生成错误

第一方生成接口的可定位错误在同一信封的 `data` 中返回：

```json
{
  "code": 1,
  "data": {
    "code": "INVALID_SETTING",
    "retryable": false,
    "fieldPath": "intent.settings.durationSeconds",
    "resourceId": "canvas-node-id"
  },
  "msg": "设置值超出允许范围"
}
```

字段说明：

- `code`：稳定的平台错误码，不暴露供应商私有错误码。
- `retryable`：客户端是否适合在不修改输入的情况下重试。
- `fieldPath`：命令中的错误字段路径；没有具体字段时可省略。
- `resourceId`：关联的 Canvas 节点或平台资源 ID；不适用时省略。

取消、回调等操作错误至少返回稳定的 `data.code`。异步失败通过 `GET /api/v1/generations/{id}` 的任务 `error` 字段返回同一套归一化信息。

## 企业基础接口

平台管理员使用现有 Bearer JWT 调用以下接口，响应继续使用统一信封：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/admin/enterprises` | 按 `keyword/page/pageSize` 查询企业、主账号、成员数和主账号余额 |
| `POST` | `/api/admin/enterprises` | 在同一事务中创建企业及唯一主账号 |
| `POST` | `/api/admin/enterprises/{id}/status` | 设置企业 `active/disabled` 状态 |
| `POST` | `/api/admin/enterprises/{id}/owner/status` | 设置主账号 `active/ban` 状态 |
| `POST` | `/api/admin/enterprises/{id}/owner/password` | 重置主账号密码并使旧会话失效 |
| `POST` | `/api/admin/enterprises/{id}/credits` | 使用 `{ delta, reason }` 按增量调整主账号积分；`delta` 不能为 0，扣减后余额不能为负 |

企业积分调整不接受客户端提交最终余额。服务端锁定主账号余额后应用 `delta`，并在同一数据库事务中写入 `admin_adjust` 流水；流水的 `userId` 是目标主账号，`relatedId` 是平台管理员，`remark` 保存调整原因。`GET /api/admin/credit-logs` 可使用 `type=admin_adjust` 筛选平台调整记录。企业账号不能再通过 `/api/admin/users/{id}/credits` 覆盖余额。

`/api/auth/login` 和 `/api/auth/me` 的公开用户信息可包含 `enterpriseId`、`enterpriseName`、`enterpriseRole` 和 `enterpriseStatus`。企业范围由服务端当前用户推导，不接受客户端提交企业 ID 来切换身份。

当前登录用户使用以下接口维护自己的账户，用户名、平台角色、积分和企业身份不能通过这些接口修改：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `PUT` | `/api/v1/account/profile` | 修改自己的昵称和邮箱 |
| `POST` | `/api/v1/account/password` | 校验当前密码后修改新密码，并使旧 JWT 失效 |
| `GET` | `/api/v1/enterprise/summary` | 有效企业账号读取企业名称、角色、状态和成员数；个人账号拒绝访问 |
| `PUT` | `/api/v1/account/enterprise` | 企业主账号修改本企业名称 |

企业主账号使用以下接口管理本企业 `member`。企业范围只从当前 JWT 对应账号推导；跨企业或非成员目标统一返回“成员不存在或无权操作”。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/v1/enterprise/members` | 按 `keyword/page/pageSize` 分页搜索本企业成员 |
| `POST` | `/api/v1/enterprise/members` | 创建固定为 `user/member`、初始积分为零的子账号 |
| `POST` | `/api/v1/enterprise/members/{id}/status` | 设置成员 `active/ban` 状态 |
| `POST` | `/api/v1/enterprise/members/{id}/password` | 重置成员密码并使旧 JWT 失效 |
| `POST` | `/api/v1/enterprise/members/{id}/credits` | 使用 `{ action, amount, requestId }` 分配或收回成员积分；`action` 为 `allocate/reclaim`，`amount` 必须为正整数 |

积分操作响应同时返回主账号最新积分 `ownerCredits` 和更新后的 `member`。客户端请求 ID 最长 128 字符；相同账号、操作类型和请求 ID 的重试只生效一次，复用请求 ID 但修改成员或数量会被拒绝。
